Desain arsitektur — HoekaGataAlgo sebagai eksekutor indikator

Dokumen requirement sebelum implementasi. Tujuan tunggal: semua keputusan trading berasal dari HoekaGataIndicator. EA tidak punya aturan sinyal sendiri — ia hanya membaca state indikator, menerjemahkannya menjadi ukuran posisi, dan mengeksekusi. Semua angka pada dokumen ini harus cocok 1:1 dengan kode MQL5 setelah implementasi.

2. State machine indikator — apa yang sebenarnya dilihat EA

Ini bagian paling penting. EA tidak melihat nama state. Ia hanya melihat apakah buffer terisi. Karena itu pemetaan di bawah harus dipahami persis sebelum menulis kode EA.

NONE (0)tidak ada setup. Buffer kosong di semua bar.
SETUP (+1)pola terdeteksi, menunggu break body. Buffer kosong.
ARMED (+2)break body kena. Buffer kosong.
ACTIVE (+3)entry terisi → BUY buffer terisi.
NONE (0)setup tidak pernah trigger.
SETUP (−1)pola SELL, menunggu break body. Buffer kosong.
ARMED (−2)break body SELL kena. Buffer kosong.
ACTIVE (−3)entry terisi → SELL buffer terisi.
Temuan kunci: buffer hanya terisi saat state sudah ACTIVE

Di Core.mqh buffer ditulis hanya pada dua tempat:

BarisSituasiArti untuk EA
~653, ~871 Blok if(flags.hitBuy || flags.hitSell) — saat bar pola terisi (fill) Fill yang sudah terjadi di masa lalu. Riwayat, bukan sinyal baru.
~981 if(state == STATE_BUY_ACTIVE) BuyBuffer[rates_total-1] = ... Level yang sedang hidup di bar terakhir. Ini yang dibaca EA.

Konsekuensi: ARMED tidak pernah muncul di buffer. EA tidak bisa dan tidak perlu memasang pending order di level BREAK BODY. EA bereaksi pada momen fill, yaitu saat state menjadi ACTIVE.

2.1 Alur keputusan EA (per tick)

OnTick() / OnTimer()
   |
   +-- 1. Source alive?          HG_SIG_<id>_HB ada & baru?  ── tidak ─> reason="Indicator not attached", STOP
   |
   +-- 2. Algo enabled?          g_algoEnabled                 ── tidak ─> reason="Manual", STOP
   |
   +-- 3. Read signal            HgSignal s = ReadSignal(shift)
   |        |                       shift = InpUseClosedBarSignal ? 1 : 0
   |        +-- _T != iTime()      ──> tolak (stale), STOP
   |        +-- _D == 0            ──> tidak ada sinyal, STOP
   |
   +-- 4. Dedupe                 s.barTime == g_lastHandledBar?  ── ya ─> STOP
   |
   +-- 5. Guards (blocking)      allowBuy/Sell · 1 posisi/simbol · minBar · jam · spread · lossLimit
   |                               ── gagal ─> reason=..., log, TIDAK set g_lastHandledBar
   |
   +-- 6. Sizing                 lot = RiskLot(dir, execPrice, sl, tp)
   |                               ── lot<=0 ─> reason="Invalid risk", STOP
   |
   +-- 7. Execute                trade.Buy/Sell(lot, exec, SL, TP)
   |                               ── sukses ─> g_lastHandledBar = s.barTime
   |
   +-- 8. Panel                  refresh

3. Kontrak data di dalam EA — struct HgSignal

Semua pembacaan indikator dinormalisasi ke satu struct. Modul lain di EA tidak boleh memanggil GlobalVariableGet atau CopyBuffer langsung. Ini yang membuat EA tetap patuh pada satu sumber kebenaran. 

struct HgSignal
{
   bool      valid;        // true bila struktur terisi & lolos validasi
   int       direction;    // +1 BUY, -1 SELL, 0 = tidak ada sinyal
   datetime  barTime;      // _T  - waktu bar sumber sinyal
   double    entry;        // _E  - level entry indikator (breakout-stop price)
   double    sl;           // _SL
   double    tp;           // _TP
   string    source;       // "gv" (GlobalVariable) | "buf" (iCustom) | "none"
   string    reject;       // alasan penolakan bila valid = false
};

3.1 Dua jalur pembacaan

JalurKapan dipakaiCaraStatus
GV (utama) Selalu, bila _HB ada GlobalVariableGet untuk _T/_D/_E/_SL/_TP; cocokkan _T dengan iTime() PERTAHANKAN
Buffer (fallback) Hanya bila GV tidak ada iCustom("HokaGATA\\HoekaGataIndicator") lalu CopyBuffer 0..3 PERTAHANKAN
Aturan urutan yang wajib
  1. GV diperiksa lebih dulu. Bila _HB ada tetapi _T tidak cocok, jangan diam-diam jatuh ke buffer — laporkan sebagai stale, karena itu tanda timeframe/simbol tidak sinkron.
  2. Fallback buffer hanya untuk kasus indikator tidak mempublikasikan GV sama sekali (versi lama / di-attach tanpa build EA-aware).
  3. Setiap pembacaan mengisi source supaya panel dan log bisa menunjukkan dari mana angka itu datang.

4. Gap analysis — kode EA saat ini vs requirement

5. Urutan eksekusi terperinci

5.1 Siklus hidup EA

OnInit()
  +-- validasi input (risk % > 0, magic != 0, spread >= 0, dst.)
  +-- trade.SetExpertMagicNumber / SetDeviationInPoints
  +-- LoadPanelConfig()
  +-- ResolveSignalSource()          : cek _HB atau cari handle iCustom
  +-- CreateControlPanel()           : hanya bila InpShowPanel
  +-- EventSetTimer(1)               : untuk panel & mode VPS
  +-- return INIT_SUCCEEDED          : TIDAK gagal walau indikator belum di-attach

OnDeinit(reason)
  +-- EventKillTimer()
  +-- StopPanelDrag()
  +-- ReleaseIndicatorHandle()
  +-- DeleteControlPanel()
  +-- TIDAK menghapus indikator (chart milik user)
  +-- TIDAK menutup posisi (posisi tetap hidup dengan SL/TP di broker)

OnTick()      : bila !InpVpsMode -> ProcessSignal(); UpdatePanel(throttled)
OnTimer()     : ProcessSignal(); UpdatePanelIfDue()
OnTradeTransaction(): update hitungan loss beruntun, auto-disable bila limit
Keputusan desain: EA tidak menutup posisi saat di-detach

SL dan TP sudah hidup di sisi broker. Menutup posisi saat EA dilepas akan mengubah hasil trading yang seharusnya sudah diputuskan indikator. Karena itu OnDeinit hanya membersihkan UI. Ini perlu disetujui secara eksplisit sebelum implementasi.

5.2 Sumber harga eksekusi

Indikator mempublikasikan level breakout-stop (_E), bukan harga pasar. Pada mode intrabar, saat state menjadi ACTIVE harga sudah melewati _E, sehingga order pasar akan terisi di harga sekarang — lebih buruk dari _E.

ModeCara EA mengeksekusiDeviasi dari indikator
A. Market (disarankan) Order pasar pada harga sekarang, SL/TP = angka indikator apa adanya Entry bisa lebih buruk (slippage), SL/TP identik
B. Market + rekalkulasi Order pasar, lalu SL digeser sejauh selisih entry→fill agar jarak risiko tetap; TP dibangun ulang dari R:R SL/TP berbeda dari indikator

Sesuai prinsip dokumen ini, Mode A menjadi default (InpRecalculateSLTPFromActualEntry = false). Mode B tetap tersedia bagi user yang lebih mementingkan R:R konsisten daripada kesamaan dengan indikator.

5.3 Rumus sizing (tidak berubah dari sekarang)

riskMoney  = ACCOUNT_BALANCE * RiskPercentForDirection(dir) / 100
slDistance = |marketPrice - signalSL|
lossPerLot = slDistance / tickSize * tickValue
rawLot     = riskMoney / lossPerLot
lot        = NormalizeVolume(rawLot)      // clamp min/max, floor ke step

RiskPercentForDirection memisahkan persen BUY dan SELL — dipertahankan karena sudah dipakai panel. Sumber kebenaran ukuran risiko tetap keputusan user, bukan indikator.

6. Batasan & risiko yang harus diterima

BatasanPenjelasan
Buffer hanya ada saat ACTIVE EA tidak bisa mem-placing order di level BREAK BODY (ARMED). Ini konsekuensi desain indikator A = P dan tidak diubah. Jika nanti dibutuhkan pending order sungguhan, itu perubahan indikator, bukan EA.
Satu sinyal, satu posisi EA tidak averaging, tidak menambah, tidak membalik arah. Semua penambahan posisi adalah keputusan di luar scope ini.
Rekonsiliasi lewat magic Posisi dianggap milik EA hanya bila MAGIC == InpMagicNumber dan SYMBOL == _Symbol. Posisi manual user tidak disentuh.
Heartbeat harus dipertahankan Indikator mem-publish _HB di setiap OnCalculate. EA menganggap sumber mati bila TimeCurrent() - _HB melebihi batas (usul: 3× periode, minimal 120 detik).
Beda timeframe = tolak Indikator mengunci _T ke bar chart-nya. EA di timeframe lain tidak akan cocok — ini fitur pengaman, bukan bug.
Tester Di Strategy Tester EA memakai iCustom (GV tidak tersedia antar-program). #property tester_indicator harus tetap ada.

7. Acceptance criteria

Implementasi EA dinyatakan memenuhi requirement bila semua poin berikut terbukti.

#KriteriaCara membuktikan
A1 Indikator tidak diubah git diff pada Main/MQL5/Indicators/ hanya berisi .ex5 hasil kompilasi ulang, bukan perubahan sumber.
A2 EA menolak jalan tanpa indikator Hapus indikator dari chart → panel menampilkan Indicator not attached, tidak ada order yang dikirim, log mencatat alasannya.
A3 EA menolak sinyal basi Ganti timeframe EA saja → _T tidak cocok → panel Signal stale / timeframe mismatch, tidak ada order.
A4 Satu sinyal = satu order Saat satu setup ACTIVE bertahan 5 bar, hanya satu posisi terbuka. Terbukti dari g_lastHandledBar + guard posisi.
A5 Tidak ada averaging / flip Saat posisi BUY hidup lalu indikator memberi SELL, EA tidak membuka SELL. Log mencatat blocked: position open.
A6 SL/TP yang terkirim = angka indikator Dengan default baru, SL/TP pada posisi identik dengan garis SL/TP di chart (bandingkan angka di panel, log, dan terminal).
A7 Lot sesuai risk % Ubah InpRiskBuyPercent → lot berubah proporsional; panel menampilkan risk money dan loss per lot.
A8 Filter lunak tidak membakar sinyal Set InpMaxSpreadPoints = 0 → sinyal dilewati; naikkan spread limit sebelum indikator mengganti sinyal → order tetap masuk.
A9 Auto-disable loss beruntun Set InpMaxConsecutiveLosses = 1 → setelah 1 losing trade, algo nonaktif dan panel menampilkan alasan.
A10 Heartbeat mati terdeteksi Saat indikator dibekukan / terminal memblokir OnCalculate lebih lama dari batas → panel Indicator stale.
A11 Kompilasi bersih Build-MT5.ps1 -Target EA → 0 errors, 0 warnings, deploy + SHA256 verified.
A12 Uji tester Strategy Tester menghasilkan trade, membuktikan jalur iCustom berfungsi.
