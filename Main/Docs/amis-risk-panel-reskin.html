HoekaGata AMIS Risk Panel

Visual requirement reference — Phase 1 (code audit) + Phase 2 (UI) specification. This file is the layout contract for Main/MQL5/Experts/HokaGATA Risk Panel/HoekaGataRiskPanel.mq5. Every dimension, colour and wording below is binding: the MQL5 panel must reproduce it 1:1. Nothing here executes trades; it is the agreed target before implementation.

Naming finding (read first). There is no file, class or symbol named AMIS in this workspace or in the local MT5 data folder. The only signal engine present is Main/MQL5/Indicators/HokaGATA/HoekaGataIndicator.mq5 v2.04 (“Engulfing Breakout”, the MT5 port of Source/HoekaGata_Engulfing.pine). This document therefore treats AMIS = HoekaGataIndicator. If AMIS is a different, separately licensed indicator, stop here and supply its source or exported buffers — the audit below must be re-run against it.

1. Phase 1 — Code audit

Consequence for §4 of the brief (Probability). No per-signal probability exists, and since the v2 layout the panel has no probability row at all — the approved screenshot shows only risk management. The rule therefore simplifies: nothing is invented and nothing is relabelled; the historical win rate stays inside the indicator’s own statistics panel. If a future revision wants it back, the smallest safe change is one extra key published per bar inside PublishSignalState(): GlobalVariableSet(SignalKey("C_PB"), nWin/(nWin+nLos)*100.0) guarded against a zero denominator, rendered as 69.7% hist. win rate — always labelled historical, never predictive.

1.2 Integration risks found in the existing code

RiskDetail / mitigation
Entry is a breakout-stop price, not a market price The state machine arms a setup at the pattern wick (STATE_BUY_ARMED = “pending at wick”) and fills only when the body-break trigger is touched. So _E is a stop-entry level. The confirmation dialog therefore states it in words (Order type: BUY STOP / SELL STOP) and the pending order is the default; a Market order exists only as an explicit user choice (Use market entry, §7.4). Silently converting a crossed stop-entry into a market order is forbidden (§6 of the brief).
Signals can be stale _T must equal iTime(_Symbol,_Period,shift); the existing EA already enforces this in ReadPublishedSignalAtShift(). The panel reuses that rule and shows an amber dot + STALE tag instead of prices.
Price already crossed the intended entry The EA dodges this with CurrentMarketEntryPrice(). Fine for a robot, but it is exactly the silent re-qualification the brief forbids for a click-to-trade panel. Panel rule: block, show Entry crossed — enable “use market” to continue, and re-enable BUY/SELL only after the user ticks Use market entry in the dialog (§7.4).
Lot sizing must not assume a fixed pip value CalculateRiskLot() uses slDistance/tickSize*tickValue, which ignores contract size, account-currency conversion and commission. Panel spec: probe both directions with OrderCalcProfit(), take the losing-side magnitude, add commission, then cross-check against the tick-value formula and surface a warning when the two differ by more than 1%.
Balance-only risk in the existing EA CalculateRiskLot() in HoekaGataAlgo_Trading.mqh hardcodes AccountInfoDouble(ACCOUNT_BALANCE) (line 481) and splits the risk by direction through InpRiskBuyPercent / InpRiskSellPercent. The panel promotes the basis to an editable Account balance ($) pill: it is prefilled from that call, and an override lets the user model a smaller account without touching the terminal. Equity as a basis is new in the panel (InpRiskBasis = Balance | Equity, default Balance, so the current behaviour is preserved); the typed override only wins while it is non-zero.
Commission double counting Panel spec: a single Commission / lot ($) pill defined as a round turn total, so there is no per-side switch that could be read twice. A broker quoting per side is entered as 2 × side rate, and the pill is labelled as an estimate for that reason. The value enters the sizing formula exactly once, inside the denominator (see §7.2).
An indicator cannot trade MQL5 indicators have no trade functions, so the panel must be an Expert Advisor even though its visual target is “the indicator’s panel”.

2. Architecture decision — Option D

Buffers and globals already carry every number the panel needs, so Option A (buffers) and the GlobalVariable channel are both viable and no change to AMIS core logic is required. Execution, however, cannot live in an indicator, so the panel is a separate EA. That is Option D: AMIS keeps generating signals; HoekaGata reads, sizes, displays and executes.

  • Read order — HG_SIG_<chartID>_* first (cheap, no handle), then iCustom() on the four buffers as fallback. Same precedence as ReadSignalAtShift() in HoekaGataAlgo_Trading.mqh, so behaviour stays identical to the existing robot.
  • Staleness — accept a setup only when _T == iTime(_Symbol,_Period,shift) and the heartbeat is younger than InpSignalMaxAgeSeconds (default 120).
  • No rewriting of AMIS — the only optional patch is the probability key in §1.1, and it is additive: a new key, no buffer index change, no state-machine change.
  • Isolation — panel objects use the HGRP_ prefix (HoekaGata Risk Panel). The indicator owns HoekaGATA_Engulf_* and the EA panel owns HGP_, so no name collisions and ObjectsDeleteAll(0, "HGRP_") is safe on deinit.
  • Coexistence — if HoekaGataAlgo is already trading the same chart, the panel warns (auto-EA active on chart) to prevent duplicate positions.

3. The panel — 1:1 visual target

340 × 457 px in the VALID state (36 title block = 12 top margin + 24 title row, 331 card, 10 title→card gap, 14 card→button gap, 54 buttons, 12 bottom pad). Each banner line adds 23 px (8 px gap + 15 px line), so the card becomes 354 px (one line) or 369 px (two) and the panel grows to 480 or 495 px. On a typical 1 200×700 chart the panel covers roughly a fifth of the plot area, so candles stay readable. Placed CORNER_RIGHT_UPPER, XDISTANCE = 12, YDISTANCE = 12 — the same slot the AMIS statistics panel uses, except that panel is 180 px wide and sits on the left chart’s right edge only when InpShowTable is on.

Scope change in this revision. The panel now shows only risk management and the two execution buttons, exactly like the approved screenshot. AMIS entry / SL / TP prices are not repeated here: they are already drawn on the chart by HoekaGATA_Engulf_* and they are repeated one last time in the confirmation dialog (§7.4). The panel’s job is the size of the bet, not the level of the entry.

7.2 Position sizing algorithm (the numbers behind 0.18)

  1. basis = BalanceOverride > 0 ? BalanceOverride : (RiskBasis == Equity ? ACCOUNT_EQUITY : ACCOUNT_BALANCE)
  2. budget = basis * riskPct / 100
  3. SL distance d = |entry − sl|, normalised to SYMBOL_TRADE_TICK_SIZE. Reject d <= 0.
  4. Probe one lot both ways: OrderCalcProfit(ORDER_TYPE_BUY, sym, 1.0, entry, sl, pBuy) and the same with ORDER_TYPE_SELL; take lossPerLot = max(|pBuy|, |pSell|) for the probe that represents the proposed direction losing. This is the step the existing slDistance/tickSize*tickValue formula cannot do for cross-currency pairs.
  5. rawLot = budget / (lossPerLot + commRoundTurn)
  6. Floor to SYMBOL_VOLUME_STEP, clamp to [VOLUME_MIN, VOLUME_MAX], round to the step's decimals.
  7. If the clamp had to raise the volume to VOLUME_MIN, re-check VOLUME_MIN * (lossPerLot + comm) > budget → state Min lot > risk. Never round up silently.
  8. OrderCalcMargin() on the final volume; compare with ACCOUNT_MARGIN_FREE.
  9. Summary rows are recomputed from the final, normalised volume — not from the raw one — so Loss at SL is what the broker will actually charge.
Worked example used by this mockup (XAUUSD, 1 lot = 100 oz, tick 0.01 = $1.00): entry 2341.55, SL 2336.10 → d = 5.45 → lossPerLot = 545.00; budget 1 % of 10 000 = 100.00; commission 7.00 round turn → rawLot = 100 / 552 = 0.1812 → step 0.01 → 0.18. Loss at SL = 0.18*545 + 0.18*7 = 98.10 + 1.26 = 99.36. Profit at TP (d = 10.60) = 0.18*1060 − 1.26 = 189.54. Margin at 1:100 = 0.18*100*2341.55/100 = 421.48 — affordable on 10 000, so the margin gate only trips once free margin falls below it (several open positions, or the smaller account modelled with the balance override).

7.3 Execution flow — BUY and SELL are the same path, opposite data

#StepRule
1Read the setup SELL button -> _C_D must be −1 and the price pair comes from _C_E / _C_SL / _C_TP of that same snapshot. BUY -> _C_D == 1. A snapshot is read atomically into a struct, then re-checked after sizing; if _T changed in between, abort with signal changed, retry.
2Validate direction geometry BUY: SL < entry < TP. SELL: SL > entry > TP. Any violation → invalid AMIS levels, no order.
3Validate freshness _T == iTime() and heartbeat age ≤ InpSignalMaxAgeSeconds. Also reject when the setup belongs to a previous bar and InpUseClosedBarSignal is off.
4Validate entry mode Pending stop (default): BUY needs entry > Ask + stops_level → ORDER_TYPE_BUY_STOP; SELL needs entry < Bid − stops_level → ORDER_TYPE_SELL_STOP. Market is only reachable through the dialog’s Use market entry tick (§7.4): without that tick a crossed entry is state Entry crossed and the flow stops.
5Size the volume §7.2, using the SL distance of the chosen side only.
6Validate the broker envelope Volume min/max/step, SYMBOL_TRADE_STOPS_LEVEL, SYMBOL_FILLING_MODE, SYMBOL_EXPIRATION_MODE for pending orders, TERMINAL_TRADE_ALLOWED, MQL_TRADE_ALLOWED, ACCOUNT_TRADE_EXPERT, and free margin.
7Confirm When InpConfirmOrders = true (default), show the summary dialog below. It must re-print the exact numbers that will be sent, including the commission estimate, the overshoot tick when the minimum volume exceeds the budget, and the Use market entry tick when the entry is already crossed.
8Send CTrade::Buy/Sell for market, BuyStop/SellStop for pending (with ORDER_TIME_GTC or the configured expiry). SL/TP normalised to _Digits, volume normalised to the step. Comment HGRP-Buy / HGRP-Sell, magic from InpMagicNumber.
9Check the retcode TRADE_RETCODE_DONE / _PLACED → success banner (teal, 4 s) with ticket. Anything else → red banner code (text) plus the full trade.ResultRetcodeDescription() in the Experts log.
10Report Never claim success on true alone: MQL5 returns true for requests that the server later rejects. The ticket and the retcode are the only proof.

7.4 Confirmation dialog (child window, not a chart object)

Rendered with OBJ_RECTANGLE_LABEL + OBJ_LABEL + OBJ_BUTTON, prefixed HGRP_DLG_, centred over the chart, closing on Cancel, Esc, or a symbol change. It is the last place a wrong direction can be caught, so the side is repeated three times: header, entry row and the coloured confirm button.

Two conditional rows sit between the commission row and the estimate banner, and only one can ever be present at a time. Use market entry (2 342.10) replaces the stop-entry when the market has already crossed _E; the confirm button stays disabled until it is ticked, and ticking it changes Order type to BUY / SELL (never silently). Accept 0.10 lot > budget replaces it when VOLUME_MIN overshoots the risk budget. Both are reset on every dialog open — acceptance is per order, never remembered.
