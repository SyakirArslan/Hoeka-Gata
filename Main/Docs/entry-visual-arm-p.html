A = P — pending hanya hidup di bar pola (visual)

Engulfing Breakout — MT5. Aturan yang dipilih: pending dipasang di candle pola itu sendiri dan hanya hidup selama bar itu. Fill juga hanya bisa terjadi di bar yang sama; kalau close bar pola belum melewati ENTRY, order dibatalkan saat bar itu close. Tidak ada pending yang menunggu ke bar berikutnya. Pasangan dokumen ini: entry-requirement-final.html (R1.1–R1.7).

Konsekuensi langsung: tidak ada state ARMED yang bertahan sampai bar berikutnya. Setiap pola selesai di bar-nya sendiri — filled atau canceled — dan panel tidak pernah menampilkan PENDING BUY / PENDING SELL.

2. Kasus cancel — pola menyentuh BREAK BODY, close belum melewati ENTRY

BREAK BODY (body top acuan + tol) ENTRY (wick + 0.10 ATR) SL (wick lawan − 0.10 ATR) Kotak kuning = bar pola = bar arming.

BREAK BODY = max(open, close) candle acuan + InpBodyBreakTol (0 di contoh ini), jadi selalu ≤ high(acuan) < close(pola) ≤ high(pola): pola sah pasti menyentuh BREAK BODY di bar-nya sendiri.

3. Kasus filled — pola juga menyentuh ENTRY

Candle yang sempat menembus ENTRY tetap filled walau close-nya kembali di bawah ENTRY, karena blok fill dievaluasi lebih dulu daripada blok cancel (R1.6). Bar 08:00 hanya melanjutkan posisi aktif.

Pola tanpa order hanya mungkin bila high(pola) belum menyentuh BREAK BODY. Dengan InpBodyBreakTol = 0 (default) BREAK BODY = body top candle acuan ≤ high(acuan) < close(pola) ≤ high(pola), jadi setiap pola pasti armed di bar-nya sendiri. Guard di EngulfComputeLevels() juga menahan BREAK BODY tetap di bawah ENTRY, sehingga kasus ini praktis tidak terjadi.

5. Kode: tiga titik evaluasi, semuanya di bar pola

Blok CREATE NEW SETUP sudah dipindah ke atas blok trigger, jadi ketiga blok di bawah ini berjalan pada iterasi bar pola (v2.02). 

// 1) arming - hanya di bar pola
if(state == STATE_BUY_SETUP && i == setup.setupBar && high[i] >= setup.pBreak)
{
   state = STATE_BUY_ARMED;
   flags.armedNow = true;
}

// 2) fill - syarat bar yang sama
if(state == STATE_BUY_ARMED && i == setup.setupBar && high[i] >= setup.pEntry)
{
   state          = STATE_BUY_ACTIVE;
   setup.entryBar = i;
   flags.hitBuy   = true;
}

// 3) cancel - setelah blok fill, bar yang sama
if(state == STATE_BUY_ARMED && i == setup.setupBar && close[i] <= setup.pEntry)
{
   flags.closeCancelNow = true;
   flags.evClose        = close[i];
   state                = STATE_NONE;   // EngulfClearSetupVisuals() hapus garis
}

Cermin SELL: low[i] <= setup.pBreak, low[i] <= setup.pEntry, close[i] >= setup.pEntry. Tidak ada perubahan pada EngulfSetup: field yang dipakai hanya setupBar dan entryBar.

Sejak v2.03 ketiga blok ini hanya berjalan untuk bar yang sudah close (guard i < rates_total - 1 di depan blok CREATE): candle yang masih berjalan tidak pernah membentuk setup, sehingga panel, counter, dan buffer EA tidak berubah di tengah candle.
